# PUB_HEALTH — Full Build & Publishing Plan
# Complete implementation brief for Cursor / AI coding agent
# Target: A Dart CLI package published on pub.dev
# Package name: pub_health
# Goal: Audit the dependency health of Dart and Flutter projects

============================================================
1. PRODUCT DEFINITION
============================================================

pub_health is a command-line tool that scans a Dart or Flutter project,
reads pubspec.yaml and pubspec.lock, queries pub.dev metadata, detects
dependency risks, calculates a project health score, and produces a
human-readable or CI-friendly report.

Core promise:
- Find outdated dependencies.
- Detect discontinued or retracted packages.
- Detect stale packages.
- Detect SDK compatibility risks.
- Detect unused direct dependencies.
- Produce terminal, JSON, and Markdown reports.
- Work safely in CI with meaningful exit codes.
- Never modify the user's project unless explicitly asked.

MVP principle:
- Read-only by default.
- Fast.
- Clear.
- Low false positives.
- Useful output.
- Easy to add to GitHub Actions.

============================================================
7. EXIT CODES
============================================================

0 = Success, no findings at or above fail threshold.
1 = At least one finding at or above fail threshold.
2 = Invalid project, missing pubspec.yaml, malformed YAML,
    or invalid CLI arguments.
3 = Network/API failure after retries.
4 = Internal unexpected error.

CI usage example:

dart run pub_health --format json --fail-on high

============================================================
8. DATA FLOW
============================================================

1. CLI parses arguments.
2. ProjectAnalyzer validates project path.
3. PubspecAnalyzer reads pubspec.yaml.
4. LockfileAnalyzer reads pubspec.lock.
5. UnusedDependencyAnalyzer scans Dart imports.
6. PubDevClient fetches metadata for each dependency.
7. Rule engine evaluates all rules.
8. HealthScorer calculates score.
9. Reporter generates output.
10. CLI returns proper exit code.

Important:
- Cache pub.dev responses in memory during one run.
- Use concurrent requests with a sensible limit, for example 5-8.
- Do not query pub.dev for Flutter, Dart, or SDK pseudo-packages.
- Handle 404, 429, 5xx, timeout, and malformed JSON gracefully.

9. PUB.DEV API USAGE
============================================================

Use the official public pub.dev API.

Package metadata:

GET https://pub.dev/api/packages/<package>

Package score:

GET https://pub.dev/api/packages/<package>/score

Publisher metadata:

GET https://pub.dev/api/packages/<package>/publisher

Useful fields:

- latest.version
- latest.published
- latest.pubspec
- versions
- tags
- discontinued
- retracted
- score.grantedPoints
- score.maxPoints
- score.likeCount
- score.downloadCount30Days

Implementation requirements:

- Create a typed PubDevPackageInfo model.
- Do not tightly couple business rules to raw JSON.
- Add retry with exponential backoff for 429 and 5xx.
- Cache successful responses for the duration of the CLI run.
- Allow a custom base URL for testing.
- Never require authentication.

============================================================
10. RULES — DETAILED SPECIFICATION
============================================================

RULE 1: outdated_dependency
ID: outdated_dependency
Severity: medium
Trigger:
- Locked version is older than latest compatible version.
Output:
- Current version.
- Latest version.
- Whether upgrade is major, minor, or patch.
Recommendation:
- Review changelog and update constraint.

RULE 2: discontinued_package
ID: discontinued_package
Severity: critical
Trigger:
- pub.dev marks package as discontinued.
Recommendation:
- Find an actively maintained alternative.
- Do not automatically remove or replace the package.

RULE 3: retracted_version
ID: retracted_version
Severity: high
Trigger:
- The locked version is retracted.
Recommendation:
- Upgrade or downgrade to a non-retracted stable version.

RULE 4: stale_package
ID: stale_package
Severity: medium
Trigger:
- Latest release is older than configurable threshold.
Default threshold: 18 months.
Exception:
- Stable, widely used packages may still be healthy.
- Use pub.dev likes, downloads, and score to reduce false positives.

RULE 5: sdk_constraint_risk
ID: sdk_constraint_risk
Severity: high
Trigger:
- Package SDK constraint does not support the project's current
  Dart SDK.
Recommendation:
- Update package or adjust SDK constraints carefully.

RULE 6: low_score_rule
ID: low_package_score
Severity: low
Trigger:
- pub points are unusually low.
- Package lacks basic documentation, tests, or static analysis.
Recommendation:
- Review package quality before relying on it.

RULE 7: unused_dependency
ID: unused_dependency
Severity: medium
Trigger:
- Direct runtime dependency has no matching import in lib/, bin/,
  or test/ source files.
Important:
- This rule can create false positives.
- Exclude known non-imported packages:
  - build_runner
  - flutter_lints
  - lints
  - analyzer
  - test
  - flutter_test
  - integration_test
  - mocktail
  - build packages
  - code generation packages
- Only run this rule for direct dependencies by default.

============================================================
11. HEALTH SCORE MODEL
============================================================

Overall score range: 0 to 100.

Start at 100.

Deductions:

- Critical finding: -25 each.
- High finding: -12 each.
- Medium finding: -5 each.
- Low finding: -1 each.

Minimum score: 0.

Example:

- 1 discontinued package: -25
- 2 outdated packages: -10
- 1 stale package: -5
- Total deduction: -40
- Final score: 60

Report should show:

Overall dependency health: 60/100
Risk level: Medium

Risk levels:

- 90-100: Excellent
- 75-89: Good
- 60-74: Medium
- 40-59: Poor
- 0-39: Critical

# pub_health

[![pub package](https://img.shields.io/pub/v/pub_health.svg)](https://pub.dev/packages/pub_health)
[![Dart SDK](https://img.shields.io/badge/Dart-3.5%2B-blue.svg)](https://dart.dev)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![CI](https://github.com/YOUR_USERNAME/pub_health/actions/workflows/ci.yml/badge.svg)](https://github.com/YOUR_USERNAME/pub_health/actions)

`pub_health` audits the dependency health of Dart and Flutter projects.

It scans your `pubspec.yaml` and `pubspec.lock`, checks dependencies
against pub.dev metadata, and reports outdated, discontinued, retracted,
stale, low-quality, and unused packages.

Unlike `dart pub outdated`, `pub_health` gives you a prioritized,
CI-friendly dependency health report.

## Features

- Detect outdated dependencies.
- Detect discontinued packages.
- Detect retracted package versions.
- Detect stale packages.
- Detect Dart SDK compatibility risks.
- Detect unused direct dependencies.
- Calculate an overall dependency health score.
- Generate console, JSON, and Markdown reports.
- Work in CI with meaningful exit codes.
- Read-only by default: it never changes your project automatically.

## Installation

Activate globally:

dart pub global activate pub_health

Or run directly in a Dart/Flutter project:

dart pub global activate pub_health
pub_health

You can also add it as a dev dependency:

dart pub add --dev pub_health

Then run:

dart run pub_health

## Usage

Run in the current project:

pub_health

Specify a project path:

pub_health --path ./my_flutter_app

Generate JSON:

pub_health --format json

Save a Markdown report:

pub_health --format markdown --output pub_health_report.md

Fail CI only for high or critical findings:

pub_health --fail-on high

Exclude packages:

pub_health --exclude build_runner --exclude flutter_lints

## Rules

| Rule | Severity | Description |
|---|---|---|
| outdated_dependency | medium | A newer compatible version is available |
| discontinued_package | critical | The package is discontinued on pub.dev |
| retracted_version | high | The locked version is retracted |
| stale_package | medium | No release for the configured threshold |
| sdk_constraint_risk | high | SDK constraint may be incompatible |
| low_package_score | low | Package has a low pub.dev quality score |
| unused_dependency | medium | Direct dependency has no detected import |

## Why pub_health?

`dart pub outdated` is excellent for checking available updates.
`pub_health` complements it by answering broader questions:

- Which dependencies are risky?
- Which packages are discontinued or retracted?
- Which packages have not been maintained recently?
- Which direct dependencies are unused?
- What is the overall dependency health of this project?
- What should CI fail on?
